# 踩坑与排查记录

开发过程中遇到的问题，按「现象 → 原因 → 解决 → 教训」整理。

## 1. 云函数报 `Cannot find module 'wx-server-sdk'`

- **现象**：审批时前端提示「操作失败」，云函数日志状态码 `443`，报错 `Error: Cannot find module 'wx-server-sdk'`。同时订阅消息也发不出去，因为推送逻辑在函数后半段，函数一加载就崩溃了。
- **原因**：用「上传并部署：云端安装依赖」部署后，云端并没有真正把依赖装上。`package.json` 里的依赖声明是正确的。
- **解决**：在云函数目录本地 `npm install`，然后改用「上传并部署：所有文件」，把 `node_modules` 一并上传。
- **教训**：
  - 日志里 `443` 是函数直接崩溃，和「函数正常执行但业务失败」是两种情况
  - 前端只显示「操作失败」，真正的原因必须去云函数日志里看

## 2. 邀请小程序码生成失败（四层问题叠在一起）

前端只提示「生成二维码失败」，实际是四个独立问题依次出现，每修一个才会暴露下一个：

| 层 | 现象 | 原因 | 解决 |
|---|---|---|---|
| ① | 云函数列表里找不到 `getInviteQrcode` | 文件夹在本地，但从来没有部署到云端 | 右键上传并部署 |
| ② | `errCode: -604101`，`function has no permission to call this API` | 云函数调用 `wxacode.getUnlimited` 需要显式声明权限 | 新增 `config.json`，声明 `permissions.openapi: ["wxacode.getUnlimited"]`；权限生效可能有延迟 |
| ③ | 声明权限后变成 `errCode: 41030`，`invalid page` | 小程序从未上传过版本，没有体验版 | 上传代码，并在版本管理里「选为体验版本」 |
| ④ | 设置了体验版，`41030` 依然存在 | `check_path` 参数默认为 `true`，即使指定了 `env_version: 'trial'`，也会去校验**已发布的正式版**里是否有这个页面 | 在调用里加 `check_path: false` |

- **教训**：
  - 云函数日志里的 `200（调用成功）` 只代表函数跑完了，不代表业务成功。这个函数内部用 `try/catch` 捕获错误后返回 `success: false`，状态码依然是 200，真正的报错藏在日志正文里
  - 云开发的日志服务需要先手动开启；刚开启时查询可能有延迟，可以用「实时日志」
  - 一次只修一层，靠日志定位，不要凭猜测改

## 3. 「管理审批人」按钮点了没反应

- **现象**：点击后没有任何反应，也没有报错提示。
- **原因**：代码用了 `wx.navigateTo` 跳转到 `pages/invite/invite`，而这个页面是 tabBar 页面。跳转 tabBar 页面必须用 `wx.switchTab`，用错了不会弹错误，只在控制台有一条错误日志。
- **解决**：改用 `wx.switchTab`。

## 4. 编辑已撤回申请时，怎么把 id 传给 tabBar 页面

- **现象**：想从「我的申请」跳到 apply 页并带上要编辑的申请 id。
- **原因**：`wx.switchTab` 不支持 query 参数，url 里带的参数会被忽略。
- **解决**：先把 id 存进 `getApp().globalData.editApplyId`，再 `switchTab`；apply 页在 `onShow` 里读取并立刻清空。

## 5. 订阅消息：几个容易忽略的规则

- **必须先授权再推送**：`wx.requestSubscribeMessage` 由用户点「允许」之后，服务端才能给他推一条。一开始只有申请人侧有授权入口，审批人侧完全没有，导致审批人永远收不到「新申请」通知。后来在 approve 页 `onShow` 补上了。
- **模板关键词是"打包"的**：模板一旦确定，每次推送都必须给**所有**关键词填值，不能只填其中几个。所以我们没有把「新申请」和「审批结果」合并成一个模板，而是分成两个。
- **字段类型有格式限制**：`thing` 类字段限 20 个字符（代码里统一 `slice(0, 20)`）；`amount` 类字段用 `Number(price).toFixed(2)`；`time` 类字段用格式化后的字符串。
- **自定义模板审核可能不通过**：自定义申请的两个模板审核未通过（没有拿到具体驳回原因），后来改成从公共模板库直接「选用」现成模板，立即生效，不需要审核。
- **服务通知只能在真机上收到**，开发者工具模拟器里收不到。
- **待排查**：审批人一侧的授权弹窗没有出现。一种可能是之前勾选过「总是保持以上选择」，系统就不再弹窗，而是沿用之前的选择，但目前还没有验证。

## 6. 开发版 / 体验版 / 正式版 与数据

- 三个版本只是**代码**的不同阶段，读写的是**同一个云环境、同一个数据库**。测试人员哪怕误点进了开发版，操作产生的数据也是真实写进库里的，不会被隔离。
- 「项目成员」自带体验版访问权限；「开发者」角色只是额外多了开发版入口。不想让测试人员看到开发版，关掉「开发者」角色即可，不需要把他们再加进「体验成员」（系统会提示已是项目成员）。
- 改了代码后，手机上的体验版不会自动更新，必须「上传」再「选为体验版本」。

## 7. 控制台提示「环境不存在，请确认当前环境和账号是否匹配」

- **原因**：浏览器里登录的腾讯云账号，和这个云环境所属的账号不是同一个。
- **解决**：换成小程序对应的微信账号扫码登录，或者直接从公众平台后台跳转到云开发控制台。

## 8. iCloud 同步 `node_modules`

- **现象**：项目放在开启了 iCloud 同步的「桌面」目录下，拖入带 `node_modules` 的云函数文件夹时，出现「正在上传 15,341 个项目」。
- **原因**：`node_modules` 里有成千上万个小文件，iCloud 会逐个同步。这和微信开发者工具的部署无关，不影响功能。
- **建议**：项目放在不被 iCloud 同步的目录；`node_modules` 通过 `.gitignore` 排除，不入库。
